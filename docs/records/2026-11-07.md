## 工具链新语法注意点(踩坑记录)

新工具链下 `--deny-warn` 会把这些当错误,写新代码时要避开:

1. `derive(...)` 后缀 → `#derive(...)` 前缀;派生 `Eq`/`Debug` 的枚举还需要
   `pub extend X with Eq::{not_equal, equal}` 与
   `pub extend X with @debug.Debug::{to_repr}`(旧的隐式提升已废弃)。
2. `not(x)` → `!x`;`StringBuilder::new()` → `StringBuilder()`;
   `starts_with` → `has_prefix`;UInt32 的 `to_int()` → `reinterpret_as_int()`;
   `Array::view(start=)` → 改用下标遍历;`String::split` 建议换 `count` 类 API。
3. 泛型函数 `fn name[T](` → `fn[T] name(`。
4. `const` 只允许原始类型;数组常量用顶层 `let`(小写命名)。
5. 可选参数 `x? : T` 不能再显式 `= None`;调用时直接传值(自动包装 Some)。
6. `raise` 的错误类型必须是真正的 error 类型(不能 `raise String`);
   labeled 参数不能按位置传;match 分支里单独的 `let` 语句要加花括号。
7. **没有 `"""` 多行字符串**;多行文本用 `#|` 前缀(moon test --update 生成
   golden 时会自动用这种写法)。
8. `derive(Debug)` 对 struct 不生效(只有枚举/已实现 trait 的载荷可用);
   结构体快照用 `Diagnostic::render()` 字符串做 golden 更稳。
9. heredoc/脚本化编辑时注意:本仓库的 shell 工具会把 `\\n` 收缩成 `\n`,
   批量改写建议走 Python(`uv run python`,用户已确认可用 uv)。
