## P2 收尾(Dahlquist 对照、多实例、Linux CI)

- **Dahlquist 对照**(`tests/integration/dahlquist_wbtest.mbt`):实测确认
  Reference-FMUs 的 Dahlquist CS 内部用**固定 0.1 步长的 Euler 子步**
  (h=1.0 通信步得到 0.9^10,而非解析解 e^{-1}),因此对照基准取内部
  Euler 离散化的闭式解 x_n = (1 - k·h)^n(k=1, h=0.1,100 步):
  - 时间网格 101 点无漂移(≤1e-9);
  - 每个 x_n 与闭式解一致(≤1e-9 相对);
  - 该闭式解同时是线性问题的严格解析参考,并顺带验证了主算法网格。
- **多实例不串状态**(同文件):从**同一个** `Fmi2Library` 开两个
  Dahlquist 实例,初始化期间把实例 b 的参数 k 改为 3,交错步进后分别
  对照 x_a = 0.9^n、x_b = 0.7^n,再让 a 单独步进 5 步确认 b 的值不动。
  踩坑:FMI 2 的 `doStep(currentCommunicationPoint, …)` 会校验时间,测试里
  必须正确推进 `time`,不能每步都传 0。
- **Linux CI**(roadmap 126 行):本地无法验证,checkbox 保持未勾,待
  GitHub Actions 首跑确认(与 P0 的 R-24 相同状态)。

## P3 · FMI 2 ME

- **`MeInstance` trait**(`src/fmi/instance.mbt`):与 `CsInstance` 平行的 ME
  接口面(setTime / 连续状态 / 导数 / 事件指示器 / 标称值 / 事件模式 /
  `newDiscreteStates` / `completedIntegratorStep`),缓冲区由调用方按
  模型描述的尺寸分配。`EventInfo` 展平了 `fmi2EventInfo` 的六个字段。
- **C shim**(`fmi2_shim.c`):ME 十个符号改为**可选解析**
  (`has_co_simulation` / `has_model_exchange` 标志),`instantiate` 增加
  接口类型参数 —— 纯 CS 或纯 ME FMU 都能加载;之前强制要求 `fmi2DoStep`。
- **绑定**(`fmi2.mbt`):`instantiate_me` + 十个 ME 方法;
  `me_instance.mbt` 把 `Fmi2Instance` 适配成 `MeInstance`。
- **加载器**(`fmu_loader.mbt`):`load_fmi2_me_fmu` 要求 ModelExchange
  接口;`state_count` 取自 ModelStructure.Derivatives 长度(无导数的
  FMU 明确拒绝),`event_indicator_count` 取自 `numberOfEventIndicators`。
- **主算法**(`src/sim/me.mbt`):`MeConfig`(solver=Euler/RK4、
  `max_event_iterations=100`)+ `run_me_simulation`:
  - 初始化后 FMU 已处于事件模式 → 先跑 `newDiscreteStates` 迭代再进
    连续模式(不能多调一次 `EnterEventMode`);
  - 每个网格步:步两端事件指示器符号变化 → 对每个 crossing 指示器二分
    (64 次上限,1e-12 精度)→ 取最早事件时间 → 积分到事件点 →
    事件循环 → **重读状态与标称值**(reinit/标称值变化);
  - 事件把时间提前后,仍在同一网格步内继续积分剩余区间 → 记录网格不漂移;
  - `SimulationResult` 新增 `events` 字段(CS 恒为 0)。
  - 关键坑:主算法推进后 FMU 还停在最后一次导数求值的状态,
    **必须 setTime + setContinuousStates 同步后再读值/进入事件模式**。
- **CLI**:`simulate --interface cs|me --solver euler|rk4`(默认 cs/rk4)。
- **测试**:mock 单元 8 个(Euler 精确网格、RK4 对 e^-t 1e-4 内、事件
  定位 1e-9、事件迭代上限、终止请求、非法配置);真实 FMU 2 个:
  VanDerPol(新增到 manifest,sha256 46e12af7…)与 h=0.001 细步长
  RK4 自收敛参考在 1e-5 内、BouncingBall ME 3 s 内 11 次事件、全程
  h≥-1e-9、终态落地。
- **文档边界**(退出标准 5):README「Known limits」声明非通用求解器。

## P4 · FMI 3 CS/ME

- **C shim**(`fmi3_shim.c`):FMI 3.0.2 全量绑定。函数按**组**解析:
  公共组(版本/释放/初始化/终止)必选,CS 组、ME 组、每个值类型组
  (Float32…UInt64/Boolean/String/Binary/Clock)、FMU state 组各自可选,
  `has_*` 标志记录 → 缺失能力调用时得到显式错误而非崩溃。
  - 官方头文件断言:`sizeof(fmi3Boolean)==1`、`sizeof(fmi3ValueReference)==4`;
  - 本工具链 MoonBit 无 `Float/Int8/Int16` 类型 → shim 层转换:
    Float32 拓宽为 Double(精确),Int8/UInt8/Int16/UInt16 拓宽为 Int32
    (shim 侧 `(ctype)` 收窄);Boolean/Clock 走 Byte 缓冲区;
  - 字符串/二进制按单变量导出(shim 负责 NUL 结尾与字节拷贝),
    字符串数组是已记录的限制;
  - `fmi2EventInfo` 同型的 `UpdateDiscreteStates` 出参展平;`fmi3DoStep`
    的四个出参(eventHandlingNeeded/terminate/earlyReturn/lastSuccessfulTime)
    展平返回;
  - 中间更新回调:noop 实现(拒绝早退),使 `eventModeUsed=true` 的
    实例化合法。
- **踩坑**:C 导出若返回 `int32_t` 而 MoonBit extern 声明返回对象
  (Bytes/Pointer),调用即段错误 —— get_string/get_binary/get_fmu_state
  统一改为「C 返回对象、状态走出参」。
- **CS 事件模式**(`fmi3_instance.mbt`):`eventModeUsed=true` 实例化,
  `exitInitializationMode` 后 FMU 处于事件模式 → 先
  UpdateDiscreteStates 迭代再 EnterStepMode 才能 doStep(漏掉这步会得到
  `fmi3DoStep: error`);step 内处理 `eventHandlingNeeded` 事件循环与
  earlyReturn 重试(本机拒绝早退,路径防御性实现)。
- **加载器**:`load_fmi3_common` 共享管线 + `load_fmi3_fmu` /
  `load_fmi3_me_fmu`;FMI 3 平台目录 `x86_64-windows/linux`;
  ME 的 state_count 取 `ContinuousStateDerivatives` 长度,
  event_indicator_count 取 ModelStructure.EventIndicators 长度。
- **CLI**:`simulate` 自动探测 FMI 版本(探测失败由加载器报精确错误),
  FMI 2/3 × CS/ME 四路分发;FMI 3 记录 Float64 标量输出(数组输出
  与 Float32 输出暂不进记录器,已注释说明)。
- **测试**(5 个):BouncingBall CS 与 FMI 2 C 参考宿主轨迹 1e-9 一致;
  Feedthrough 全类型 roundtrip(Float64/Int32/UInt64/Boolean/String);
  StateSpace 数组(尺寸经结构参数 r=vr3 读取,u/y roundtrip,与
  e^0.1 解析解差 ~5.5e-5 = FMU 内部积分离散化);BouncingBall ME
  (RK4 + 事件);FMU state 保存/恢复(轨迹精确重放)。
- **FMPy 对比**:本机无 FMPy/Python,交叉检查以 FMI 2 C 参考宿主与
  解析解代替;fmi-cross-check 集成仍属 P8(G-02)。
- **SE 可行性结论**(C-19):Scheduled Execution 需要时钟调度器、
  `ActivateModelPartition` 与分区间一致性保证;Reference-FMUs 无 SE
  样本可验证。结论:**不实现**,维持「首版只支持固定间隔、单速率」的
  设计边界(master-algorithm.md §5),如需 SE 走外部调度器。
