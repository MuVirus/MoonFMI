## Phase 2 · C-11 CS 主算法硬化(Discard 回滚 + 重试)

- **发现真实缺陷**:FMI 3 `fmi3_fail_on_failure` 只拦 Error/Fatal,`Discard`
  状态静默流过且被当成"已到达 t+h"——FMU 实际可能只推进到
  `lastSuccessfulTime`,主算法却记录虚假时间。
- `CsInstance` trait 新增(MoonBit `= _` 默认实现语法,参考 core 的 Logger):
  - `try_step(t, h) -> Double`:返回 FMU 实际到达时刻;
  - 回滚表面 `supports_state_capture` / `begin_rollback_point` / `rollback` /
    `commit_rollback_point`(默认"不支持")。
- `SimulationError` 新增 `Discarded(detail~, last_successful_time~)`。
- 主算法(`cs.mbt`):Discard → 有捕获则回滚 + 步长减半重试(上限
  `max_discard_retries = 5`,下限 `min_retry_step = 1e-12`);无捕获时 FMI 3 用
  `lastSuccessfulTime` 续跑(网格点用完整步长),FMI 2 明确报错。硬错误路径
  释放已武装的捕获状态;后端 `free()` 兜底释放。
- 后端:FMI 2(`cs_instance.mbt`)`try_step` 把 Discard 报为 `Discarded`
  (FMI 2 无 lastSuccessfulTime);FMI 3(`fmi3_instance.mbt`)重构出共享
  `Fmi3Instance::fmi3_cs_advance`(step 与 try_step 共用),Discard 带
  `lastSuccessfulTime` 上抛;**回滚武装期间 `fmi3DoStep` 以
  `noSetFMUStatePriorToCurrentPoint = fmi3False` 调用**(规范 §3.5 要求)。
- 测试:`src/sim/cs_rollback_wbtest.mbt` 5 个 mock 用例(回滚减半网格、
  FMI 2 形状拒绝、FMI 3 确认进度续跑、重试上限、干净运行 begin/commit 配对)。
- 文档:`master-algorithm.md` §3.5 改为已实现语义;backlog C-11 ✅。

## Phase 3 · C-08 收尾(FMI 2 Integer/Boolean 绑定)

- shim(`fmi2_shim.c`):解析 `fmi2Get/SetInteger`、`fmi2Get/SetBoolean`(按组
  解析 + `has_integer_boolean` 标志);四个导出包装 + 能力标志查询。
- MoonBit(`fmi2.mbt`):`get/set_integer`、`get/set_boolean`(数组 + one 变体),
  能力缺失报 `Fmi2CapabilityMissing`,长度不匹配报新变体
  `Fmi2InvalidArgument`。
- **调试中抓到并修复自己引入的真实 ABI 缺陷**:新 shim 包装把
  `(c, vr, values, nvr)` 传成了 `(c, vr, values, count)`——FMI 2 签名是
  `(c, vr, nvr, value)`(nvr 在 value 前)。段错误定位路径:测试 0xc0000005 →
  shim fprintf 追踪(参数值正确)→ SEH 捕获出错地址 → 对照
  `llvm-objdump -d` 反汇编发现 FMU 收到的"values 指针"是整数 1(count)→
  修正四处调用顺序。同时用纯 C 探针确认语料 FMU 本身完全正常。
- 测试:`tests/integration/feedthrough_wbtest.mbt` 3 个真实 FMU 用例
  (Feedthrough 的 Int32/Boolean input→output 直通 roundtrip + 长度校验拒绝)。
- backlog C-08 ✅(String 通道 FMI 2/3 导入侧均无需求,记录边界)。
