# 实施记录：2026-11-22 · 0.8.1 需求缺口收尾

> 目标：把需求清单核对出的六个缺口全部收掉——ME time event 调度、FMI 3
> 六种 setter、数组 get 与记录器、CS/ME 时钟调度与跨 FMU 时钟连线、
> MD-007/MD-052 自身码与规则正例矩阵、Stair/Roberts 语料——并对齐版本
> 政策（最小递增）与文档残留。范围与决策（白盒 mock 验证时钟、couple
> 连线本次实现）经用户确认。

## 背景

0.8.0 发布后按需求清单逐项核对：FMI 2 CS、FMI 3 CS/ME 运行时、CLI 四命令、
库用法、语料获取与安全测试均已实现且 222 个测试全绿；但 ME 主循环从不消费
`nextEventTime`（`docs/records/2026-11-18-b.md` 的声称与代码不符）、FMI 3
set 侧缺 Float32/UInt8/Int16/UInt16/UInt32/Int64、数组 get 仅 Float64 且
CLI 不输出数组、时钟级联只在 SE、MD-052 未实现且 backlog 误标、Stair 与
Roberts 已进清单但没有测试运行。

## 交付清单

1. **ME time event（`src/sim/me.mbt`）**：`me_event_iteration`/
   `me_settle_event` 返回最终 `EventInfo`；循环体顶部算 `event_cap`，以
   `next_event_time_defined` 为门（未定义时读 0.0，无门会卡死在 t=0）钳制
   adaptive 步长与 fixed 网格内子步；落到事件时刻即进入事件模式结算
   （`completedIntegratorStep` 不要求也会进入）；fixed 路径记录保持网格
   （`grid_target` 与 `step_end` 分离）。FMI 3 ME 共用此 master。
2. **FMI 3 setter（`src/backend/native/fmi3.mbt`）**：6 个 extern + 包装 +
   `set_*_one`（C shim 宏早已生成全部符号与能力标志，零 C 改动）；
   `src/cli/sets.mbt` 的 `SetValueKind` 扩到 8 种，`--set` 覆盖全部数值类型。
3. **数组（`fmi3.mbt`/`fmi2_instance.mbt` 系）**：10 个数值类
   `get_<t>_values`；三个 trait 加 `read_real_values`（默认实现逐元素，
   FMI 2 用连续 VR、FMI 3 用 nValues 覆盖）；`RecordedArray` 进
   CsConfig/MeConfig/SeConfig；CLI `real_outputs_fmi3` 用
   `fmi3_element_count`（pub 化）展开 `name[i]` 列。
4. **时钟（`src/sim/clocks.mbt` 新）**：SE 激活轮次提炼为
   `run_clock_rounds` + `ClockSchedule` 状态，`ClockScheduling` 以闭包绑定
   实例（沿 `SeConfig.trigger` 先例，规避 trait-object 字段的不确定性）；
   CS 每通信点、ME 每次事件结算（事件模式内）跑轮次；
   `fmi3_cs_advance` 消费 `nextEventTime` 拆分 do_step；shim 把
   `fmi3GetIntervalDecimal`/`fmi3ActivateModelPartition` 拆为独立 flag
   （官方 CS/ME 实例化签名没有 clockUpdate 回调参数，探查阶段的一条
   "缺失"判断据此修正）；CLI 自动为声明了时钟的 FMI 3 模型接线。
5. **couple 时钟连线（`src/sim/coupling.mbt`）**：`SignalType::Clock` +
   `ParticipantClocks` 钩子；时钟连接不进信号计划与代数环分析，每个
   通信点后观察源输出时钟、命中即触发目标输入时钟；两端缺钩子报 Config。
6. **校验规则（`src/schema`）**：`structure_error`/`optional_enum`/
   `parse_int32_value` 加可选 `code~` 参数；MD-007、MD-052 发自身码；
   schema_wbtest 增加 46 条规则的数据驱动正例矩阵与两条新反例。
7. **语料（`tests/integration/stair_roberts_wbtest.mbt` 新）**：Stair
   fmi2/fmi3 CS（整数计数器走类型化通道）与 Roberts fmi3 ME。
8. **版本与文档**：`cli.mbt` 版本对齐 `moon.mod`（0.8.1）+ 根包一致性
   测试；CHANGELOG 版本政策与 [0.8.1] 节；退出码旧表同步；`.mjs` 残留
   （doctor/tests/data README/tests/abi README）；新增
   `docs/guides/quick-start.md` 并登记文档地图；master-algorithm.md
   记录器注记与 §5.3 CS/ME 复用；backlog §10.2 增量与两条 open 项
   （Roberts CS、自建时钟测试 FMU）。

## 验证

- `moon build --target native` 0 错误；`moon test --target native`
  全绿：根包 1、schema 47、sim 39、cli 36、integration 75（0.8.0 基线
  222 → 241）。
- `moon info` 接口变化集中在 `src/fmi`（`read_real_values`）、`src/sim`
  （`ClockScheduling`/`RecordedArray`/config 新字段）、
  `src/backend/native`（新 setter/get_values/`fmi3_clock_metadata`）、
  `src/cli`（`version_string`）——均为只增不改，JSON 契约未动。
- SE 集成时间线（Clocks.fmu 15 次激活）在调度器重构后逐值不变；ME 参照
  轨迹（VanDerPol/BouncingBall）在 nextEventTime 钳制下全部中性。

## 探查修正

- 官方 FMI 3 头文件里 CS/ME 实例化没有 `clockUpdate` 回调参数（仅 SE 有），
  "把回调传给 CS/ME 实例化"不可行也无需做：CS/ME 的输出时钟经事件模式
  后由宿主 `fmi3GetClock` 观察。
- `fmi3/Clocks.fmu` 只有 ScheduledExecution 接口，CS/ME 时钟路径无官方
  样品可用，验证采用 mock 白盒（用户确认），自建时钟 FMU 记入 backlog。

## 遗留（记录在案）

- Roberts CS 需要宿主实现 intermediate-update 通道（crosscheck.md 已记录）。
- CS/ME 时钟与跨 FMU 连线目前只有 mock 白盒证据；自建最小时钟 C 测试 FMU
  是下一步的硬化项（backlog §10.2）。
- ME 记录器仍只收 Float64；Int32 等类型走类型化通道（master-algorithm
  §5.2 注记）。
