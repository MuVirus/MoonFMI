# 2026-10-30

搭建 MoonFMI 的工程基础设施：9 个包的骨架、依赖方向检查、Windows/Linux 自动检查、8 个真实 FMU 测试语料，以及可选的官方 XSD 对照。

---

## 1. 9 个包的骨架

| 包 | 依赖 | 目标 | 内容 |
| --- | --- | --- | --- |
| `src/zip` | 无 | 全平台 | `ZipArchive` 占位 |
| `src/xml` | 无 | 全平台 | `XmlLimits`，默认 32 MB / 256 层 |
| `src/schema` | `xml` | 全平台 | `FmiVersion`、`ModelDescription` 占位 |
| `src/fmi` | `schema`、`zip` | 全平台 | `Fmu` 占位 |
| `src/backend/native` | `fmi` | native | `NativeBackend` 占位 |
| `src/backend/wasm` | `fmi` | wasm | `WasmBackend` 占位 |
| `src/sim` | `fmi` | 全平台 | `SimulationConfig` 占位 |
| `src/export` | `schema`、`zip` | 全平台 | `ExportRequest`、`ExportTarget` 占位 |
| `src/cli` | `export`、`sim` | 全平台 | `Command` 枚举与默认值 |

核心包不设置 `supported_targets`，只有 `backend/native` 写 `"native"`、`backend/wasm` 写 `"wasm"`。

每个包一个白盒测试。两个目标各自排除对方的后端，所以每个目标各跑 8 个测试：

```text
Total tests: 8, passed: 8, failed: 0.
```

过程中处理了两个 MoonBit 工具链细节：

- `pub enum` 的变体在包外只读，跨包构造需要 `pub(all) enum`；
- `derive(Eq, Debug)` 在 `--deny-warn` 下触发 `implicit_impl_as_method`，改为显式 `pub extend ... with Eq::{...}` 与 `@debug.Debug::{to_repr}`，并在 `moon.pkg` 导入 `moonbitlang/core/debug`。

## 2. 依赖方向检查

新增 `tools/check-deps.mjs`，按 [`architecture.md`](../design/architecture.md) 的分层读取每个 `moon.pkg`：

```text
zip, xml                         → 无
schema                           → xml
fmi                              → schema, zip
backend/native, backend/wasm     → fmi
sim                              → fmi
export                           → schema, zip
cli                              → 上面全部
```

脚本同时检查：

- 是否出现反向依赖；
- `backend/native` / `backend/wasm` 是否设置了正确的 `supported_targets`；
- 核心包是否误设 `supported_targets`。

自检：

```text
$ node tools/check-deps.mjs --self-test
dependency checker self-test passed
```

故意在 `src/zip/moon.pkg` 加入 `src/schema` 导入，检查器报错：

```text
$ node tools/check-deps.mjs
Dependency check failed:
  src/zip imports src/schema, but the allowed directions are: (none)
```

## 3. 自动检查与 CI

新增 `.github/workflows/ci.yml`：

- `ubuntu-latest` 与 `windows-latest` 两个 job；
- MoonBit 版本固定为 `0.1.20261023`；
- Linux 使用官方 `install/unix.sh`，Windows 使用官方 `powershell.ps1`；
- Linux 额外执行 FMU 取件与校验；
- 最后检查工作树是否有未同步的生成文件。

本地脚本与 CI 使用同一套步骤：

| 步骤 | 命令 |
| --- | --- |
| 依赖方向 | `node tools/check-deps.mjs` |
| 格式 | `moon fmt --check` |
| 编译 native | `moon check --target native --deny-warn` |
| 编译 wasm | `moon check --target wasm --deny-warn` |
| 测试 native | `moon test --target native --deny-warn` |
| 测试 wasm | `moon test --target wasm --deny-warn` |
| 公开接口 | 删除 `.mbti` → `moon info` → 对比哈希 |
| XSD 对照 | `pwsh` / `powershell` 调 `validate-xsd.ps1`（可选，失败只警告） |

入口：

- `scripts/check.sh`：Linux / WSL / Git-Bash；
- `scripts/check.ps1`：Windows PowerShell。

公开接口检查特意放在 `moon check` 之前记录哈希。原因是 `moon check` 也会更新 `pkg.generated.mbti`，如果只在末尾比较，手改或过期的接口会被悄悄修好：

1. 脚本开始时记录所有 `.mbti` 的 SHA-256；
2. 删除这些文件，重新执行 `moon info`；
3. 与开头的哈希对比，不一致就失败。

新增 `.gitattributes`，统一固定 LF：

```text
* text=auto eol=lf
```

避免 Windows 的 `core.autocrlf` 与 `moon fmt` 的 LF 输出互相冲突。

缓存布局：

```text

  Reference-FMUs.zip
  fmi2/*.fmu
  fmi3/*.fmu
```

校验失败示例：

```text
$ node tests/data/fetch-fmus.mjs --offline
cache is incomplete or corrupt:
  sha256 mismatch: .cache\fmi2\BouncingBall.fmu (expected 1c7a40ab..., got 63b7cc39...)
run without --offline to download the samples
```

```text

  size mismatch: .cache\fmi2\BouncingBall.fmu (expected 218148, got 218149)
```

```text

```

发布包仍在缓存时，删除单个 FMU 再从缓存包重新解压即可，不需要联网。

## 5. 官方 XSD 对照

没有实现 XSD 引擎，也没有把 XSD 接进 MoonBit 代码。XSD 只作为外部对照工具，用来区分「解析器错」和「样品本身坏」。

本机没有 Python / `xmllint`，改用 PowerShell + .NET `System.Xml.Schema`：

- Windows：`powershell`
- Linux / CI：`pwsh`
- XSD 是仓库内可信文件，允许解析相对 `xs:include`；
- 实例文档 `XmlResolver = $null`；
- `DtdProcessing = Prohibit`；
- `MaxCharactersInDocument = 32MB`；
- 不联网。

5 个样品与结果：

| id | 类别 | XSD 预期 | 结果 |
| --- | --- | --- | --- |
| `fmi2-valid` | 完全合法 | 通过 | ✅ |
| `fmi3-valid` | 完全合法 | 通过 | ✅ |
| `fmi2-missing-guid` | 结构错误（缺必填） | 失败 | ✅ |
| `fmi2-unknown-index` | 结构合法但语义错误 | 通过 | ✅ |
| `fmi2-external-entity` | 外部实体 | 失败 | ✅ |

`fmi2-unknown-index` 是关键：`<Unknown index="99">` 指向不存在的变量，XSD 仍然通过，说明语义引用必须由单独的语义校验器处理。

运行结果：

```text
$ powershell -NoProfile -ExecutionPolicy Bypass -File tests/data/validate-xsd.ps1
PASS  fmi2-valid  (expected pass)
PASS  fmi3-valid  (expected pass)
PASS  fmi2-missing-guid  (expected fail)
PASS  fmi2-unknown-index  (expected pass)
PASS  fmi2-external-entity  (expected fail)
all 5 XSD cases behaved as expected
```

目前还缺「超大文件」「元素顺序错」「枚举值非法」三个样品，后续补。
