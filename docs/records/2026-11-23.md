# 实施记录：2026-11-23 · 0.8.2 遗留项收尾（Roberts CS + 自建时钟 FMU）

> 目标：关闭 0.8.1 记录的两条遗留——Roberts CS 与“CS/ME 时钟路径只有
> mock 证据”。探查推翻了 Roberts 的旧归因，实现分三块：event-mode
> 回退实例化、intermediate-update 通道做实、自建时钟 fixture
> MoonfmiClocks。范围与方案经用户批准（计划模式）。

## 背景

0.8.1 遗留两条 open 项。对上游 v0.0.42 源码的逐字核对得出关键事实修正：
Roberts 的 `config.h` 未定义 `EVENT_UPDATE`，其二进制在
`eventModeUsed=true` 时拒绝实例化（XML 却声明 `hasEventMode`），而
MoonFMI 硬编码了 `eventModeUsed=true`——与 intermediate-update 通道无关
（该 FMU 不检查回调指针与 required 列表，doStep 每 1e-6 内部步调用一次
回调且忽略宿主早退请求）。旧归因散落在 crosscheck/backlog/测试注释。

## 交付清单

1. **event-mode 参数化与回退**：`moonfmi_fmi3_instance_new` 加
   `event_mode_used`/`early_return_allowed` 参数；`load_fmi3_fmu` 按 CS
   接口的 `has_event_mode` 定初值、实例化失败回退 `false`；
   `CsInstance::initialize` 仅在 eventModeUsed 下跑事件结算与
   EnterStepMode（否则 FMU 已在 StepMode，再调是非法序列）。
2. **intermediate-update 通道**：shim 回调从“计数+拒绝”升级为“计数 →
   MoonBit thunk（time + 四个标志）→ 回传宿主早退决定”，宿主早退只在该
   FMU `canReturnEarly` 时生效、时刻即回调时刻；`earlyReturnAllowed` 按
   `mightReturnEarlyFromDoStep || canReturnEarlyAfterIntermediateUpdate`
   决策；`fmi3Instance::intermediate_update_count` accessor；
   `CsInstance::intermediate_update_count`（默认 0）。FuncRef 参数只有
   FFI 原生类型（FixedArray 指针不能过回调边界——首次实现的
   `int32_t*/double*` 出参导致 fail-fast，已改为返回 Int32 协议）。
3. **MoonfmiClocks fixture（`tests/clock-fmu/`）**：手写 C FMU（CS+ME
   接口、3 输入时钟 + outClock、Int32 计数器 + Float64 镜像、一个平凡
   连续状态）；doStep 内部 0.05 步进、每步调回调并响应宿主早退请求；
   `tests/integration/clock_fmu_wbtest.mbt` 测试内编译（clang）+ 确定性
   zip 打包 + 加载，clang 缺失整组 SKIP。手写 XML 需注意：根元素顺序为
   ModelExchange 在 CoSimulation 前，ModelStructure 内
   ContinuousStateDerivative 在 InitialUnknown 前——两条都踩过。
4. **验收测试**：Roberts CS（0→0.02，动力学判据同 ME + ~2 万次回调
   断言）；MoonfmiClocks 四类端到端——CS 网格轮次时间线（constant 逐
   网格 / triggered 每点 / countdown 0.2s 重武装）、ME 事件模式轮次
   （constant 按“事件点追及”补跑，事件数 1）、instance 级早退协商
   （宿主 t≥0.05 请求 → FMU 两次响应 → step body 续推到 0.1）、couple
   跨 FMU 时钟连线（A.outClock 脉冲 → B.inClock 触发计数 2）。
5. **文档**：crosscheck 归因更正；backlog §10.3 记录并关闭两条 open；
   master-algorithm §5.3 注明两层验证与 ME 追及语义；tests/abi/README
   修正退役脚本残留（.ps1/.mjs → .mbtx）；CHANGELOG [0.8.2]。

## 验证

- `moon build --target native` 0 错误；`moon test --target native` 全绿
  （0.8.1 终点 239 → 245：Roberts CS + MoonfmiClocks 四类 + 根包版本锁
  0.8.2）；clang 缺失路径由 SKIP 分支保证不挂（本机 clang 在 PATH，SKIP
  分支由 compiler_probe_skip 模式保证）。
- CLI 冒烟：`moonfmi version` → 0.8.2。
- mbti 变化集中在 backend/native（instantiate 参数、count accessor、
  Fmi3IntermediateUpdate 类型）与 fmi（CsInstance 新方法）——只增不改。

## 探查修正

- Roberts CS 归因：binary/XML 失配（无 EVENT_UPDATE 拒 eventModeUsed）
  而非缺 intermediate-update 通道——crosscheck.md、backlog、测试注释
  三处已改。
- FuncRef 回调参数必须是 FFI 原生类型；FixedArray[Int32]/[Double] 出参
  会在 FMU→shim→MoonBit 回调边界 fail-fast。

## 遗留（记录在案）

- MoonfmiClocks 的 ME 侧 constant 时钟按事件点追及语义验证；SE/CS 的
  网格点语义已在 CS 用例覆盖。

# 追加：examples/ 可运行示例（同日）

> 目标：补上仓库一直缺失的 `examples/` 目录。写文档约定
> （`.agents/skills/write-docs/references/guide.md`）明确要求“可运行证明放
> `examples/`”，quick-start 也要求“完整代码链到 `examples/`”，但该目录一直
> 不存在——backlog 的 G-05「文档/示例/迁移」被标 ✅ 属于漏项。本节记录补齐
> 的过程。

## 交付清单

1. `examples/common/`：示例共用的小工具——命令行参数、失败退出、按 FMI 版本
   收集输出列、CSV 渲染。目标中立，native 与 wasm 都能编。
2. `examples/validate-model/`：打开归档 → 校验模型描述 → 打印摘要与诊断。
   不加载动态库，因此没有平台依赖。
3. `examples/simulate-cs/`：加载 FMU → CS 主算法 → CSV。演示 FMI 2/3 的
   版本探测与两套加载器如何汇合到同一个 `CsInstance` 接口。
4. `examples/simulate-me/`：ME 主算法（Euler / RK4），并演示 ME 特有的
   `state_count` / `event_indicator_count` 从哪来。
5. `examples/couple-fmus/`：Dahlquist 驱动 Feedthrough 的一次耦合仿真。
   连线两端都**按变量名反查 value reference**——value reference 只在单个
   模型描述内有效，写死数字是错的做法。
6. `examples/export-source-fmu/`：模型 IR → 源码 FMU → 确定性 `.fmu`，并把
   生成的 `modelDescription.xml` 喂回自己的校验器，证明导出与导入闭环。
7. `examples/README.md`：总览、前置条件、运行方式，以及 `moonfmi` 的命令行
   速查（命令、常用选项、退出码、配置层）。
8. `scripts/check.mbtx`：新增 “examples” 步骤，逐个跑上面的示例。示例是会
   腐烂的文档，跑进门禁才不会。

## 验证

- `moon fmt`、`moon check --target native --deny-warn`、
  `moon check --target wasm --deny-warn` 全绿（零警告）。

## 探查修正

- Dahlquist（Reference-FMUs v0.0.42）的输出变量叫 `x`（vr=1），不是 `y`；
  语料里 `y` 只是导出器示例模型的名字。耦合示例按名查找，第一次跑就暴露了
  这个差异。
- Dahlquist 的 CS 实现按自己的 0.1 步长推进（每个宿主步长里 x 才动一次），
  所以耦合示例把步长取 0.1，每行都能看到变化；这不是宿主侧的 bug。

## 遗留

- 示例的 FMU 输入默认指向语料缓存（`tests/data/.cache/`），照抄进自己的
  工程时需要换成自己的路径，或先跑 `moon run tests/data/fetch-fmus.mbtx`。
- 导出的 `.fmu` 是源码 FMU（没有编译好的动态库），要真正跑还得用生成的
  `CMakeLists.txt` 编出 `binaries/<平台>/` 再重新打包。
