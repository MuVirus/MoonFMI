# 实施记录：2026-11-20 · moonfig 接入（CLI 配置层）

> 目标：把同作者的 MoonBit 配置库 `moonfig` 接入 MoonFMI，让 `simulate`/`couple`
> 支持配置文件与环境变量输入，并把 moonfig 的能力缺口收进专门台账，供后续集中
> 反馈上游。依赖准入按 `AGENTS.md` §13.3 流程执行（先告知、后改 `moon.mod`）。

## 背景

CLI 此前只有命令行一种输入通道：17 个长选项分散在 6 个手写解析点，取值域靠
逐条字符串比较；没有配置文件入口；环境变量只用于 `doctor` 读 `PATH` 和
`--sandbox` 的子进程标记。后果是"一套仿真实验规格"无法存盘——CI 里只能把
一长串参数抄进命令行，实验不可复现、不可审阅。

方案与取舍见 [`../design/config-layer.md`](../design/config-layer.md)。

## 依赖准入

- 模块 `MuVirus/moonfig@0.2.4`（mooncakes 核实为最新：2026-11-20 15:11 UTC 发布，
  build_status success，Apache-2.0，下载量 285，依赖者 0）。
- 传递依赖仍只有 `moonbitlang/x@0.5.7`（本项目已锁同一版本），**零新增传递依赖**。
- 只引 `core` + `core/format/{json,ini,dotenv}_format` + `file_source`/
  `env_source`/`format_detect`；不引 `moonfig-toml`/`moonfig-yaml` 适配器。
- 0.2.3 → 0.2.4 是破坏性变更（环境变量分隔符改为按需开启、`CliSource` 接受
  负数值），故必须锁 `@0.2.4`。
- 评估记录写入 [`../research/moonbit-ecosystem.md`](../research/moonbit-ecosystem.md) §13.1。

## 交付清单

1. **`src/cli/config.mbt`（新）**：配置层全部实现。
   - 键空间按命令分节（`simulate`/`couple`），内部统一 snake_case，配置文件额外
     接受 kebab-case 别名。
   - 来源顺序：命令行 > 环境变量 > 配置文件 > 内置默认；合并用**字段级回填**——
     只填命令行留空的字段，不覆盖命令行已有值。
   - 环境变量走 `EnvSource::new("MOONFMI_").with_separator("__")`：
     `MOONFMI_SIMULATE__STOP_TIME` → `simulate.stop_time`。0.2.4 起环境变量默认
     只按 `.` 分层，不显式开分隔符会得到平键、配置静默不生效。
   - 格式判定用 `format_detect`（JSON/INI/dotenv），错误经 `map_config_error`
     包一层后映射到退出码：Io → 1，语法/类型/取值 → 2。
   - 未知键只 `eprintln` 警告，不失败；只检查 `simulate`/`couple` 两段
     （其它 `MOONFMI_*` 根键属别的工具，如 `MOONFMI_SANDBOX_CHILD`、
     `MOONFMI_WASM_BIN`）。
2. **`src/cli/cli.mbt`**：新增 `--config <path>`；`interface`/`solver`/`backend`
   由 `String` 改 `String?`（否则无法区分"命令行显式给了 cs"与"没给"，优先级
   无从实现）；默认值推迟到消费点由 `effective_interface/solver/backend()`
   解析；`--timeout` 的秒→绝对截止时间换算抽成 `deadline_in_seconds()`，
   公式与原实现一致；`usage()` 与 `command_help` 补 `--config` 说明。
3. **`src/cli/moon.pkg`**：新增 7 个 moonfig 包导入；**`moon.mod`**：锁
   `"MuVirus/moonfig@0.2.4"`。moonfig 只进 `src/cli`（该包
   `supported_targets = "native"`），`src/fmi` 不引入，wasm 构建不受影响。
4. **文档**：新建 [`../design/config-layer.md`](../design/config-layer.md)（状态
   "已实现"）与 [`../roadmap/moonfig-gaps.md`](../roadmap/moonfig-gaps.md)
   （G-01..G-09 能力缺口台账）；更新 `README.mbt.md`、`docs/design/README.md`、
   `docs/roadmap/README.md`、`docs/references/links.md`、生态评估 §13.1、
   `docs/design/cli-and-testing.md`（`--config` 选项与 `couple` 命令）。

- `moon fmt`：无额外文件被改。

## 探查修正（规划阶段的事实订正）

- moonfig 0.2.4 的包图实测为：`core`（纯计算、零 IO）、
  `core/format/{json,ini,dotenv}_format`（平台无关）、`file_source`（x/fs）、
  `env_source`/`cli_source`（core/env）、`format_detect`、`hot_reload`；
  TOML/YAML/XML/CBOR/serde 是独立适配器模块。
- "`moonfig` 只能在 native 跑"不成立：`moonbitlang/x/fs` 与 `moonbitlang/core/env`
  都有 js/native/wasm 三套实现；真正的约束来自 MoonFMI 自己的包分层。
- `ConfigError` 是 `pub(all) suberror`，变体为 MissingKey / TypeMismatch /
  ParseError / IoError / MergeConflict / InvalidValue / UnknownKey / UnknownFormat。

## 遗留（记录在案）

- **S4（命令行解析迁到 `CliSource`）暂不实施**：0.2.4 已解除表达能力限制
  （G-03 关闭），保留自研解析的理由改为行为兼容性——错误消息文本与退出码是
  对外契约，`src/cli/cli_wbtest.mbt` 锁定退出码。
- **来源追踪未做**：moonfig 的 `Config::snapshot()` 能给出每个键的来源，但写进
  `--json` 会动 [`../cli-json.md`](../cli-json.md) 的 schema 契约；需要时再做独立
  子命令 `moonfmi config`。
- **数组型配置无法用环境变量表达**：`set`/`connect` 只能来自配置文件或命令行
  （一个变量一个值，同键多值会报 ParseError）。记为缺口 G-09。
- **缺口台账 G-08 仍开放**：mooncakes 上发布的模块级 README 仍写"This is the
  core module"，与 0.2.4 的包结构不符。
- 本轮改动**未提交**（工作区有 14 个改动/新增文件），待用户确认后再提交。
