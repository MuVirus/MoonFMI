# README

README 面向使用者：能做什么、怎么开始。设计取舍不写在这里，放 `docs/`，用链接指过去。

- 仓库根：`README.mbt.md` 是英文版（权威），`README_ZH.md` 是中文版，`README.md` 是指向英文版的符号链接。改一边就改另一边。
- 结构：首屏就要能看出这是什么、怎么用。
  - **定位**：一句话说清是什么、给谁用、覆盖哪些标准或范围。不写背景故事，不写设计取舍。
  - **功能**：3–6 条使用者视角的能力，一条一句；再细的说明链到 `docs/`，不枚举 API。
  - **安装**：前置条件 + 最短的可复制命令；发布渠道与源码构建并列写明。
  - **最小示例**：一条命令或一段代码，复制即可运行，只证明一个点；语料下载、初始化等必要步骤放这里。
  - **用法**：日常命令或 API 的短清单和典型组合；参数、退出码、JSON 契约链到文档，不抄 `--help`。
  - **已知限制**：只写「看起来支持、实际不支持」的边界，尤其是实验性能力；没有就省略。
  - **文档与许可证**：文档入口、设计与路线图链接、许可证名称。
- 文档区先链 `docs/AGENTS.md`（本仓库的文档入口）；完整任务步骤放 `docs/` 的对应文档，README 只给链接和一两句结论。
- 代码块标语言。片段用 `moonbit nocheck`，不参与校验；需要保证能跑的例子放 `///` 注释的 `mbt check` 里。
- 不搬运 `moon doc` 能生成的 API 清单，不写内部架构宣言和开发约定。
